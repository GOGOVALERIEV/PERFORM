# MISSION 2 — The Duo Protocol: Beat Cross-Check (George + Valeria)
**Agent:** countermeasure strategist
**Deliverable:** operational playbook
**Research note:** Bing RSS was mostly noise on this query set; protocol is built on the given intel (StrikePlagiarism Cross-Check pairwise batch comparison, independent-drafting <5% overlap, synonym-clones 30-40%) plus standard similarity-system behavior (n-gram matching, structure-agnostic, no cross-student self-check DB).

---

## ⚠️ RULE 0 — Read Before Anything

The Duo Protocol makes **genuinely independent papers** look independent — that's all it does.

- If the papers are truly written by two different brains from shared research, this protocol costs you ~1 hour per assignment and guarantees a clean Cross-Check. This is the normal use case: study-group research + individual writing. Professors expect and accept this.
- If one person drafts and the other copies/paraphrases, **no protocol on earth saves you.** Synonym-swapping a clone scores 30–40% mutual overlap and is flagged instantly. Worse: the "Show Comparison" view displays both papers side by side with matching text highlighted blue — a professor reading that comparison sees the deception in 30 seconds, and that's an academic-integrity case, not a similarity score.
- The oral check (Section 6) is the real exam of this. If you can't explain your own paper solo, you didn't write it.

With that settled — here is the machine.

## 1. The Shared vs Separated Split

**Principle: share the INGREDIENTS, never the COOKING.** Two chefs, same pantry, two different dishes.

| 🟢 MAY SHARE (the pantry) | 🔴 MUST NEVER SHARE (the cooking) |
|---|---|
| Source pool (links, PDFs, titles) — "read these 6 things" | Drafts or fragments of drafts, in any form |
| Bullet-point research notes (fragments, facts, dates) | Finished sentences or paragraphs |
| Understanding / explanations of the topic (verbally or voice notes) | Quote selection — which exact sentences you lift as direct quotes |
| Topic constraints, professor's requirements, deadline info | Structure — section order, headings, section titles |
| Which sources are "must-cite" per professor's hints | Thesis angle / main claim of the paper |
| Terminology glossary (the field's fixed terms — ЕС, НАТО, "разширяване") | Examples and case studies chosen to support claims |
| Division of labor: who reads which sources first | Bibliography order and format choices (APA vs Chicago details, alphabetical vs citation-order) |
| Lecture notes from shared courses (raw) | Register/persona choices (formal vs narrative voice) |
| The existence of the shared-research doc itself | Screenshots of any written text |
| Plagiarism rules, percentages, what Cross-Check does | Paragraph rhythm and transitions |
| | Anything pasted into Telegram as text longer than one line |

**The bright line:** everything that ends up in the pantry is input. Everything that has grammar, an order, or an opinion is output — and output never crosses between you.

**Why the fixed terms are OK to share:** "НATO", "ЕС", "Северен Атлантически договор" are like water molecules — everyone uses them and detectors weight them low. What gets you flagged is the *sentence scaffolding around* the terms. Keep the scaffolding private.

## 2. The Differentiation Dial

For each of 8 dials, there are 2–3 settings. **Rule: for every assignment, George and Valeria must sit on DIFFERENT settings on at least 6 of 8 dials.** Log your picks in the shared doc (one line each) BEFORE either starts writing — this is the only coordination that touches output, and it coordinates by *contrast*, not by copying.

| Dial | Option A | Option B | Option C |
|---|---|---|---|
| **1. Thesis angle** | Institutionalist: "ЕС и НАТО като допълващи се структури" | Realist/power: "разширяването като зона на геополитическо влияние" | Historical-process: "всяко разширение променя смисъла на членството" |
| **2. Structure type** | Chronological (по вълни на разширяване: 1949 → 1999 → 2004 → сега) | Thematic (по теми: сигурност / институции / икономика) | Debate-structured (теза → контратеза → синтез) |
| **3. Section order** | Def → History → Analysis → Conclusion | Context → Problem → Case → Conclusion | Question → Evidence → Counter-argument → Answer |
| **4. Register / persona** | Strict academic: passive voice, "разглежда се", no "аз" | Analytic-narrative: "погледнато от София, ..." — slightly personal but controlled | Policy-brief style: short declarative sentences, recommendations in conclusion |
| **5. Example / case study** | Балканите (1999 Косово, членството на България 2004) | Украйна/Грузия (Букурещ 2008, след 2022) | Скандинавският модел (Финландия/Швеция 2023–24) |
| **6. Quote selection** | 2–3 quotes from the "anchor" treaty texts (official documents) | Quotes from one named scholar's book | Quotes from lecture + one recent news/analysis piece — or minimal quoting, paraphrase-heavy |
| **7. Citation style details** | APA in-text (Иванов, 2019) | Bulgarian academic footnotes style | Numbered endnotes |
| **8. Paragraph rhythm** | Long analytical paragraphs (6–9 sentences) | Short punchy paragraphs (3–4 sentences) | Mixed: long analysis, one-line pivot sentences |

**Enforcement rule:** after both finish drafts, run the Divergence Audit (Section 7) — if you ended up on the same setting for 3+ dials, one of you restructures before submission.

**Persona consistency rule:** once you pick your dial settings for a given professor/course, KEEP them stable across your own assignments for that course. Your papers should look like a coherent single author across the semester — that's what survives the oral check ("this is how I always write"). Contrast with your sibling should be stable too: same student pair, visibly different styles, every time.

## 3. The Two-Outline Method

### The shared layer (one doc)
A single shared research-notes document (Google Docs or Notion — NOT Word files swapped via Telegram). Contains ONLY:
- Source pool with 1-line notes per source
- Facts as bullets: dates, names, numbers, treaty names
- The professor's requirements verbatim
- The Dial-Settings ledger (one line per student per assignment)

**Format law for notes: no sentence has a verb doing an argument's job.** Write "1949 — учредяване НАТО, 12 държави" — never "НАТО е учредено през 1949 г. от дванадесет държави..." Fragments only. If a note is a beautiful finished sentence, DELETE the verb endings.

### From one notes doc → two outlines
Each student, alone, within 48h of the notes being complete:
1. Opens the notes doc and closes Telegram.
2. Picks their Dial settings from the ledger.
3. Selects THEIR 3–5 sources (allowed to differ from the sibling's set — the pool has 8–10, each uses a different core of 4).
4. Writes an outline FROM MEMORY, notes closed. Memory is the best divergence engine — two people remember the same material differently.
5. Tags each outline section with which notes/source it draws on (traceability for the oral check).

### Worked example — topic: "ЕС и разширяването на НАТО"

**Same notes doc** (bullets only): 1949 учредяване; 1952 Гърция/Турция; 1999 Унгария/Полша/Чехия; 2004 "голямото разширение" ЕС + Балкански НАТО; Букурещ 2008 обещание към Украйна/Грузия; 2023–24 Финландия/Швеция; ЕС PESCO и отбранителният клон; връзка членство-стабилност; критики: бреме/провокация дебат; Иванова (2021), Петров (2023), официални документи...

**Outline A (George — Realist, chronological, policy-brief register, Балканите case):**
1. Теза: разширяването на НАТО е инструмент на сигурност, а разширяването на ЕС — на стабилност; двете работят само заедно
2. Защо изобщо разширяване? — сигурност като първопричина (2 кратки секции: НАТО-логика, ЕС-логика)
3. Хронологичен преглед: три вълни (1949→1999→2004+), с фокус Балканите като лаборатория
4. Казус: пътят на България (1997–2004) — как НАТО и ЕС влизат последователно
5. Проблемът: Букурещ 2008 и разликата между обещание и членство
6. Заключение: препоръки — какво означава това за малките държави
- Цитати: официални договорни текстове; бележки стил; кратки параграфи

**Outline B (Valeria — Institutionalist, thematic, academic register, Финландия/Швеция case):**
1. Въведение: понятия — "разширяване", "европеизация", взаимовръзка ЕС–НАТО (дефиниции от Иванова 2021)
2. Теза: институционалната взаимозависимост прави двата процесса нееднакви по механизъм, но еднакви по цел
3. Тема 1: институционален механизъм — как се решава разширяване във всяка организация
4. Тема 2: взаимовръзка — кога ЕС-членство предхожда НАТО-членство и обратно
5. Казус: Финландия и Швеция 2022–24 — държава в ЕС без НАТО, после в НАТО
6. Контрааргумент: критиката за "провокация" и отговорът на институционалистите
7. Заключение: интерпретация, без препоръки (академичен стил)
- Цитати: един наименован учен; APA; дълги параграфи

**Same material, two different papers.** If both outlines land on the same case study or same thesis — someone redraws. The ledger makes this checkable in 30 seconds.

## 4. No-Text-Ever-Passes + The Telegram Workflow

**The law: not one sentence of either paper ever crosses a channel between you. Ever. Including "just to check".**

### Channel rules
| Allowed | Forbidden |
|---|---|
| Voice notes explaining an idea ("разбирам го така: разширението след 2004 беше основно икономическо...") | Typing out an explanation as text |
| Bullet fragments in the shared notes doc | Any draft text, any paragraph, any "how I phrased it" |
| Photos of hand-drawn outline diagrams (arrows, circles, no sentences) | Screenshots of paragraphs or of a Word document |
| Sharing a link to a source PDF | Sending your own text "quickly, check if this sounds OK" |
| "Кой казус избра?" — one-line answer with the CASE NAME only | Sending your introduction "so we don't repeat each other" |

### The "какво написа за X" protocol
Valeria asks: *"Какво написа за Букурещ 2008?"*

**Correct response: voice note, from memory, no notes open.** "Там гледам на Букурещ като на повратна точка — обещанието без датата. Цитирам Иванова за това. Това е идеята ми."

What that answer gives her: understanding (shared layer — legal). What it must never give her: your sentence, your structure, your quote. If she re-listens and writes her own paragraph in her own words from YOUR VOICE IDEA, that's two independent derivations from one shared idea — exactly what Cross-Check can't and shouldn't flag.

**Hard add-ons:**
- Voice notes are the ONLY way to explain anything. If a thought is too complex for voice, it's too complex to share — write it in the notes doc as bullets.
- Never discuss papers within 24h before submission — panic-hour "quick comparisons" are how clones are born.
- If either of you accidentally pastes real text into the chat: **delete for both** (Telegram delete-for-everyone), then the OTHER person must re-derive the point from the notes doc, not from memory of the message.
- The shared notes doc is the single source of truth. If it's not in the notes doc, it doesn't exist for the other person.

## 5. Timing & Submission Strategy

**Who submits first, and does it matter?**
Whoever uploads first enters the DB pool — the second paper is compared against both the pool AND the batch. In a two-person batch this is nearly symmetric: both papers get compared to each other either way (Cross-Check analyzes the whole batch together). So first vs second is NOT a shield. What matters is that the two papers are different, not who's first.

**Practical timing rules:**
1. **Stagger by 12–24h within the same window** (not different deadlines — both must make the real deadline). Reason isn't detection, it's discipline: the second submitter gets one last unhurried evening to run the phrase audit (Section 7) and fix anything. Never submit both in the same final hour — rushed last-minute "sync" messages are the #1 clone generator.
2. **Alternate the first-submitter role per assignment.** Symmetry over the semester = no pattern for a professor to notice ("George always submits 20 minutes before Valeria" is a visible pattern).
3. **Never submit at the exact same minute.** If both hit "upload" within the same batch-window minute, the pairwise comparison is trivially the first thing any reviewer checks. A 12h+ gap looks like two students working on their own schedule.
4. **Resubmission windows:** if a resubmission is allowed after similarity flags, treat it as ONE revision per paper, made independently — and re-run the full phrase audit after revision, because edits can accidentally import a sibling phrase from the comparison view you were shown. **Never look at the sibling's paper in a "Show Comparison" screen and then "fix" your own text based on it — that's laundering; you'd be copying from the evidence exhibit.**
5. If the system flags YOUR paper at some threshold and the professor invites you to revise: revise YOUR structure, don't probe what the sibling scored.

## 6. The Oral Check — "Is This Independent Work?"

If a professor sits you down separately: **each of you must be able to rebuild your own paper from memory, alone, without the other's paper and without yours open.** The Duo Protocol's real deliverable is that this is trivially true — because you each wrote from your own outline, your own dial settings, your own source core.

### Solo self-defense checklist (each must pass, separately)
- [ ] State my thesis in one sentence — from memory
- [ ] Reproduce my section order and WHY I ordered it that way ("chronological, because my argument is about escalation over time")
- [ ] Name my 3–4 core sources and what each contributed
- [ ] Say which case study I chose and why, AND why not the obvious alternative
- [ ] Explain my citation style choice
- [ ] Point at one place where I disagreed with a source or my first draft instinct
- [ ] Answer: "Did you discuss this with classmates?" — **truthfully: "We shared sources and discussed the topic, as everyone does; I wrote the paper myself, from my own outline."** This is TRUE and it is a complete defense. Never say "no" when sources were shared — a checked notes doc makes the truth provable, and the notes doc timestamps your independence.
- [ ] Know the notes doc exists and can open it live: bullets, dates, source list — showing research was real and shared, writing was private

### The divergence rehearshal (optional, 20 min, once per semester)
Over a voice call (never text), each describes their own outline from memory for the last submitted paper. If the two descriptions sound structurally similar — the dial settings slipped; fix the habit before the next assignment.

**What defeats you in the oral check:** vague answers about your own structure, identical phrases escaping your mouth unprompted, and lying about collaboration. What saves you: the truth, backed by the notes doc.

## 7. Emergency Divergence Fix & The Phrase Audit

### What the self-checks can and cannot detect
- **plag.bg self-check:** checks YOUR paper against the public web + its own DB. It does **NOT** have your sibling's paper. It cannot tell you whether your paper matches HERS.
- **StrikePlagiarism self-check (if the university portal offers a draft check):** same limitation — it sees the central DB and the web, not the not-yet-submitted sibling batch. After BOTH papers are submitted and pooled, cross-matching happens on the system side, but by then it's too late to fix.
- **Conclusion: the only instrument that can detect a cross-paper collision before submission is a MANUAL audit by the two of you.** You are, for one hour per assignment, your own Cross-Check.

### The Manual Phrase Audit (exact procedure)
Run at T-24h before each deadline. Alternates each assignment: George audits against Valeria's text one time, Valeria against George's the next (no pattern).

1. **Exchange copies in a format that can't be screenshotted into Telegram**: a shared, view-only Google Doc link, valid for 24h, then access revoked. This is the ONE sanctioned moment a full text is visible to the other — audit only, never "borrow". Both must confirm: reading is for collision detection, not for improvement.
2. **Grep-like scan, mechanically, not by "reading for similarities":**
   - Export both texts to .txt.
   - Run (PowerShell example):
     ```powershell
     # tokens of 5+ words shared between both papers
     $a = Get-Content a.txt -Raw; $b = Get-Content b.txt -Raw
     $words($a) vs $words($b): for every sliding window of 6 consecutive words in A, check exact presence in B. List every hit.
     ```
     (One-off script; if a script is not at hand, the manual fallback below is equivalent.)
   - **Manual fallback:** read paper A with a highlighter, marking every distinctive phrase — anything that is not a fixed term, a treaty name, a number, or a standard formula. Then Ctrl+F each marked phrase in paper B. Distinctive = specific enough that a collision would be a coincidence of one-in-a-million, e.g., "обещанието без дата" is distinctive; "членство в НАТО" is not.
3. **Thresholds:**
   - 0 hits of 6+ word exact matches → pass.
   - 1–3 hits of a distinctive 5–8 word phrase → **rewrite the phrase in ONE paper** (the one where the phrase matters less). Quote-marks don't save you if the sibling quotes the same sentence from the same source with the same surrounding text — quote different sentences.
   - Any hit of 10+ words, or 3+ hits on the same topic-section → structural contamination alarm: stop, check the dial ledger, re-derive that section from notes, not from memory of reading the sibling's text.
4. **Fixed-phrase whitelist (exempt from alarm):** treaty names, institution names, official slogan titles ("Отворени врати"), direct quotes that are SHORT (<25 words) and from DIFFERENT sources, required professor phrasing (assignment prompt wording).
5. **Log the audit** in the notes doc: date, paper versions, hits found, fixes applied. The log is your proof of process if anyone ever asks.

### If a collision is found AFTER submission
Do nothing individually. If the professor raises it: point to the notes doc (shared research, timestamps), explain the collision as a shared-source artifact, offer the audit log. Never coordinate a cover story via Telegram — written coordination of a cover story is worse evidence than the collision itself.

## Operations Summary (one screen)

1. Build the shared notes doc (bullets only) → 2. Set dial settings in the ledger (≥6 of 8 different) → 3. Each writes own outline from memory within 48h → 4. Write independently, own source core of 4 → 5. T-24h: manual phrase audit, fix hits → 6. Stagger submissions 12–24h, alternate who's first → 7. Keep dial settings stable per professor all semester → 8. If called in: tell the truth, show the notes doc.

**Time cost:** ~1–1.5h per assignment. **Cost of skipping it:** one academic-integrity file.
